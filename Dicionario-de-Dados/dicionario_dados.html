Dicionário de Dados - Oya Cell

Este dicionário de dados foi elaborado para organizar e explicar as principais informações utilizadas no sistema proposto para a Oya Cell.

As entidades foram definidas a partir das informações levantadas durante a pesquisa de campo e dos processos identificados na empresa, principalmente relacionados a clientes, pedidos, produtos, pagamentos e controle de estoque.

Os dados apresentados neste documento servem apenas para representar a estrutura do sistema. Informações pessoais reais de clientes não são apresentadas.

1. Cliente

Armazena as informações básicas dos clientes atendidos pela Oya Cell.

Atributo Descrição Regra de Negócio
id_cliente Identificador do cliente. Cada cliente deve possuir um identificador único.
nome Nome do cliente ou da empresa. O nome deve ser informado no cadastro.
cpf_cnpj CPF ou CNPJ utilizado para identificar o cliente. O documento deve estar relacionado ao cliente cadastrado.
contato Informação utilizada para entrar em contato com o cliente. O contato pode ser utilizado durante o atendimento e acompanhamento do pedido.

2. Produto

Representa os componentes e acessórios comercializados pela Oya Cell.

Atributo Descrição Regra de Negócio
id_produto Identificador do produto. Cada produto deve possuir um identificador único.
codigo Código utilizado para identificar o produto. Cada produto deve possuir um código para facilitar sua identificação.
descricao Nome ou descrição do produto. A descrição deve permitir que o produto seja identificado.
categoria Indica a categoria do produto. O produto pode ser classificado, por exemplo, como componente ou acessório.
preco Preço de venda do produto. O produto deve possuir um preço válido para sua comercialização.
quantidade_estoque Quantidade disponível do produto. A quantidade deve ser atualizada de acordo com as entradas e saídas do estoque.

3. Pedido

Registra os pedidos realizados pelos clientes.

Atributo Descrição Regra de Negócio
id_pedido Identificador do pedido. Cada pedido deve possuir um identificador único.
data_pedido Data em que o pedido foi realizado. A data deve ser registrada no momento da realização do pedido.
valor_total Valor total do pedido. O valor é obtido a partir dos produtos e das quantidades do pedido.
status Indica a situação atual do pedido. O pedido pode estar em separação, saiu para entrega, finalizado ou cancelado.
forma_recebimento Indica como o cliente receberá o pedido. O pedido pode ser retirado no balcão ou enviado para entrega.
id_cliente Identifica o cliente responsável pelo pedido. Todo pedido deve estar relacionado a um cliente.

4. Item do Pedido

Representa cada produto que faz parte de um pedido.

Atributo Descrição Regra de Negócio
id_item Identificador do item. Cada item do pedido deve ser identificado.
id_pedido Identifica o pedido ao qual o item pertence. Todo item deve estar relacionado a um pedido.
id_produto Identifica o produto incluído no pedido. Todo item deve estar relacionado a um produto.
quantidade Quantidade solicitada daquele produto. A quantidade deve ser maior que zero.
preco_unitario Preço do produto no momento da venda. O preço utilizado na venda deve ficar registrado no item.
subtotal Valor daquele item dentro do pedido. É calculado considerando a quantidade e o preço unitário.

5. Pagamento

Registra os pagamentos realizados para os pedidos.

Atributo Descrição Regra de Negócio
id_pagamento Identificador do pagamento. Cada pagamento deve possuir um identificador único.
id_pedido Identifica o pedido relacionado ao pagamento. Todo pagamento deve estar relacionado a um pedido.
forma_pagamento Forma escolhida para realizar o pagamento. Pode ser PIX, cartão de débito, cartão de crédito ou boleto.
valor Valor registrado no pagamento. O valor do pagamento deve ser maior que zero.
data_pagamento Data em que o pagamento foi realizado. A data da operação deve ser registrada.
status_pagamento Indica a situação do pagamento. Permite acompanhar se o pagamento foi confirmado ou ainda está pendente.

6. Funcionário

Representa os funcionários envolvidos nos processos da Oya Cell.

Atributo Descrição Regra de Negócio
id_funcionario Identificador do funcionário. Cada funcionário deve possuir um identificador único.
nome Nome do funcionário. O nome deve ser informado no cadastro.
funcao Função exercida pelo funcionário. Permite identificar sua responsabilidade dentro da organização.

7. Funcionário e Pedido

Registra a participação dos funcionários nos pedidos. Essa estrutura é necessária porque um pedido pode envolver mais de um funcionário e um funcionário pode participar de vários pedidos.

Atributo Descrição Regra de Negócio
id_funcionario Identifica o funcionário. Deve estar relacionado a um funcionário cadastrado.
id_pedido Identifica o pedido. Deve estar relacionado a um pedido existente.
participacao Indica a participação do funcionário naquele pedido. Permite registrar a atuação do funcionário no processamento do pedido.

8. Movimentação de Estoque

Registra as entradas e saídas dos produtos, ajudando no controle da quantidade disponível no estoque.

Atributo Descrição Regra de Negócio
id_movimentacao Identificador da movimentação. Cada movimentação deve possuir um identificador.
id_produto Identifica o produto movimentado. Toda movimentação deve estar relacionada a um produto.
id_funcionario Identifica o funcionário responsável pelo registro. A movimentação deve permitir identificar quem realizou o registro.
tipo_movimentacao Indica o tipo de movimentação. Deve indicar se a movimentação é uma entrada ou uma saída.
quantidade Quantidade de produtos movimentada. A quantidade informada deve ser maior que zero.
data_movimentacao Data em que ocorreu a movimentação. A data da movimentação deve ser registrada.

9. Estorno

Registra a devolução de valores ao cliente quando ocorre um cancelamento que permite estorno.

Atributo Descrição Regra de Negócio
id_estorno Identificador do estorno. Cada estorno deve possuir um identificador único.
id_pagamento Identifica o pagamento relacionado ao estorno. Todo estorno deve estar relacionado a um pagamento.
valor_estornado Valor devolvido ao cliente. O valor deve respeitar a regra de cancelamento aplicada ao pedido.
percentual_estorno Percentual utilizado para calcular o valor devolvido. O estorno pode ser integral ou de 60%, dependendo da situação do pedido.
data_estorno Data em que o estorno foi realizado. A data da operação deve ser registrada.

Considerações finais

O dicionário de dados foi desenvolvido para manter as informações do projeto organizadas e facilitar o entendimento do modelo de dados. A estrutura proposta busca atender principalmente às necessidades identificadas nos processos de pedidos e controle de estoque da Oya Cell.
